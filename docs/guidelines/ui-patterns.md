# UI patterns

How views and components look and behave, so every new screen stays consistent with the existing ones. Components live in [`packages/ui`](../../packages/ui/README.md) and are documented in Storybook; tokens are described in [design-tokens.md](design-tokens.md); code layout and naming are in [code-conventions.md](code-conventions.md); texts follow [voice and tone](../product/voice-and-tone.md). Why the patterns are encoded this way: [ADR-0019](../decisions/0019-encode-ui-standards-in-tokens-and-the-library.md).

## Tokens

- Views and components use only semantic tokens: `--color-bg`, `--color-fg`, `--color-fg-muted`, `--color-line`, `--color-surface`, `--color-highlight` (the current position on a scale, such as the timeline's reading line), `--color-stage-*`, `--size-content-*`, `--duration-*` and the scales for spacing, type and borders. Palette tokens such as `--color-neutral-950` are used only inside `design/tokens.json`.
- When a view needs a colour or size with a new role, add a semantic token for that role instead of reaching for the palette or a literal value.
- Spacing is a multiple of 4 from the `--spacing-*` scale. Border widths come from `--border-width-*`; corners are square (`--border-radius-none`); there are no shadows.
- A literal value is fine only for something that belongs to one component and has no shared role, for example the height of the artwork stage on a phone.

## Layout

- Mobile first. There is one breakpoint, `@media (min-width: 768px)`. CSS variables cannot be used in media queries, so the number is written out and only this one is allowed. Where a phone-only counterpart is needed, it is `@media (max-width: 767.98px)`, so the two ranges neither overlap at 768 px nor leave a gap for fractional widths.
- Content width: every form (artwork, value, glossary entry, event) limits its fields to `--size-content-default` (720 px), like text and lists, so the forms have the same width; single-column panels use `--size-content-narrow` (400 px); the artwork wall uses `--size-content-wide` (1280 px) and is centred.
- The pages before signing in (start, sign-in, sign-up, password reset and update, terms and privacy) share `PublicPage`: a sticky header with the logo (a link to `/`) and, on the right, only the account actions the page does not offer itself ([ADR-0148](../decisions/0148-show-each-account-action-once-before-signing-in.md)): "Zaloguj się" on the start page, nothing above a form (sign-in, sign-up, password reset and update), "Zaloguj się" and "Załóż konto" on the legal pages (on a phone only "Zaloguj się"), and "Przejdź do atelier" for a signed-in learner everywhere but the new password page. Full-height parts of these pages subtract `--public-header-height`; the panels carry no logo of their own.
- Spacing between elements comes from the parent (`display: grid` or `flex` with `gap`). Elements do not set their own outer margins; `base.css` resets them, and the start padding of `ul` and `ol` too, so a list sets only `list-style: none`, while a list that keeps its markers, such as a list in notes, sets its own `padding-left`. Stylelint allows only `0` and `auto` for `margin*`; the few exceptions, such as the wall's bar group, are listed under `margin` in `lint/allowlist.json`.
- Each route group has a layout component in its domain folder, for example `AuthLayout` for the sign-in screens. A view passes its content through snippets (`children`, `footer`).
- `AuthLayout` (the start page and the sign-in screens) shows the artwork twice from 768 px: as the background under `--color-scrim` and in a `Frame` on top. On a phone the stage shows only the background with the caption, because a framed image that small is hard to see.
- Views of the signed-in learner use `AtelierLayout`: the menu as an icon rail from 768 px and as a bottom bar on a phone, and a sticky top bar whose content the view passes as the `bar` snippet. The rail keeps its expanded or collapsed state across navigation and reloads on the same device (`study-atelier:rail-expanded` in `localStorage`); the menu sheet of a phone closes after a link is picked. The top bar runs across the full width of the page beside the menu in every view ([ADR-0031](../decisions/0031-full-width-top-bar-in-every-atelier-view.md)): the way back, the name of the view or both on the left, the actions on the right. The name of a view is its `h1`, in the look of a page title, rendered by `AtelierLayout` from its `title` with `heading` ([ADR-0243](../decisions/0243-name-the-view-in-the-top-bar.md)). The bar has the same height in every view, `--size-control` plus its padding, whatever the view puts in it.
- On a phone `AtelierLayout` puts a bottom bar (`BottomBar`) across the screen in place of the rail: "Atelier", "Słowniczek", "Dodaj", "Powtórki" and "Menu", each an icon over its name at 11 px, the current one bright with a line above it and its name in medium weight ([ADR-0252](../decisions/0252-overhaul-the-app-on-a-phone.md)). "Powtórki" carries the number due today in a `Count`, and "Menu" the mark of something new in the career. "Menu" opens a sheet from the bottom (`BottomSheet`) with the logo, the account row and the modules that are not in the bar (Kartoteka, Kalendarium, Kronika, Wystawy, Ekspozycja), then Archiwum, "Zgłoś uwagę", the theme and signing out. "Dodaj" opens a sheet "Dodaj" with four tiles in a fixed order, "Dzieło", "Pojęcie", "Wizyta" and "Wydarzenie", named "Dodaj dzieło" and so on; the tile of the current module (the glossary, the chronicle, the timeline, otherwise the artwork) is highlighted, and a tap opens its form.
- There is one bar at the bottom of a phone at a time. A task leaves out the bottom bar and keeps its own actions: a form with `FormActions` (found by `data-action-bar`), and a view that passes `task` to `AtelierLayout` (a running review, an exhibition in edit mode, Ustawienia); every task has a visible way out ("Anuluj", "Przerwij" or the back arrow). `AtelierLayout` sets `--bottom-inset` to the height of the bottom bar with the safe area of the screen, and to 0 in a task and from 768 px; the content, a fixed letter index, "Zacznij powtórkę" and a `Toast` stand above it.
- In the top bar only the back arrow stands at the left, and the action buttons, grouped, always stand at the top right (`BackLink` grows to fill the bar, a group that stands alone has `margin-inline-start: auto`; the bar itself packs its items from the start). A module (Atelier, Kartoteka, Słowniczek, Kalendarium, Kronika, Wystawy, Powtórki, Ekspozycja, Archiwum) has no back arrow, and the menu moves between modules; its name stands first in the bar, except on the wall, whose search and tools stay centred over the wall without a name. Statystyki and Ustawienia, which are not menu items, start the bar with `BackLink` with `arrowOnly` ("←" alone, the name "Atelier" kept for assistive technology), passed as the `back` snippet, then their name ([ADR-0243](../decisions/0243-name-the-view-in-the-top-bar.md)). A detail page (an artwork, a value, a glossary entry) starts its top bar with `BackLink`: "← " and the name of the place the learner came from (a module by its name, another detail page by the thing's name), going back through the browser history; opened directly, it links to its own list ("Atelier", "Kartoteka", "Słowniczek"). A form starts its top bar with the same `BackLink`, named after the page that opened it, and keeps its title only as a visually hidden `h1`; opened directly, an edit form links to the record it edits, by its name (an artwork, a glossary entry, an event, a visit by its place), and an add form to its list; after an add form, the new page's arrow names the page that opened the form ([ADR-0106](../decisions/0106-name-where-the-arrow-of-a-form-leads.md)). `AtelierLayout` names every page from its `title`, and the root layout keeps the place each history entry was reached from in a SvelteKit `snapshot`, so a page visited twice and the browser's back and forward buttons each show their own way back ([ADR-0101](../decisions/0101-go-back-to-where-the-learner-came-from.md)).
- Every view named in the top bar opens its content with the library `PageHeader`: the lead and a hairline in `--color-line` right under it, across the content; the `h1` is in the bar ([ADR-0243](../decisions/0243-name-the-view-in-the-top-bar.md)). A count of the view (the entries of Słowniczek, the visits of Kronika) stands at the right, level with the lead (`aside`, with tabular figures on the count only), and a control of the view that is not part of a toolbar in the content, such as "Filtry" in Kalendarium, stands at the top right, level with the lead (`actions`). On a phone `PageHeader` is not shown, so the content starts at once: an empty module explains itself with its `EmptyState`, and "Filtry" of Kalendarium moves to the top bar ([ADR-0252](../decisions/0252-overhaul-the-app-on-a-phone.md)). The wall is the one exception: a presentation, with the title and the count in the content but no lead and no line, also on a phone, since the count opens Statystyki. Statystyki and the display case keep their own headers without an `h1`, since their sections open with lines of their own; on a phone Statystyki drops its lead too, and the display case keeps it, because it has no empty state to explain the career.
- The add action of a module stands at the right of its top bar from 768 px. In Słowniczek, Kronika and Kalendarium it is the library `AddButton`: a `primary` link with `plus` and the full label ("Dodaj pojęcie", "Dodaj wizytę", "Dodaj wydarzenie"), and the wall keeps "Dodaj dzieło" among its tools ([ADR-0243](../decisions/0243-name-the-view-in-the-top-bar.md)). On a phone none of them is shown, because "Dodaj" of the bottom bar adds ([ADR-0252](../decisions/0252-overhaul-the-app-on-a-phone.md)); Wystawy has no add action on a phone ([ADR-0238](../decisions/0238-hide-adding-an-exhibition-on-a-phone.md)), and Kartoteka keeps its own in its tools.
- On a phone `BackLink` shows the arrow alone and keeps the name of the place for assistive technology, so the actions of the bar fit.
- A top bar action with an icon and a label is a `Button` with `icon` and `compact`, which shows only the icon on a phone; it also has an `aria-label` with the label. A page that was not found or failed to load shows `LoadFailure` instead of its content: the message (a lead when not found, a danger `Alert` when the load failed) and a button back to its list.
- A list a detail page returns to keeps its state in a page `snapshot`, restored on a history return only: the wall, Słowniczek (search, categories and the scroll position, set again once the categories are back, because SvelteKit scrolls before it restores the snapshot and the browser's scroll anchoring then keeps the entry that was on screen in the full list in view), Kartoteka (tab, search and the scroll position, set again the same way, because a restored search hides values too) and Kalendarium (era, scale, place, selection, filters and switches).
- "Zgłoś uwagę", between "Archiwum" and the theme switch, opens the `FeedbackDialog` hosted by `AtelierLayout`: kind as `ChoiceTiles` (Błąd, Pomysł), title, description, and a toast after sending ([ADR-0076](../decisions/0076-collect-feedback-in-a-table-from-a-menu-dialog.md)). On a phone the menu sheet closes first.
- The theme is dark by default; the menu item between "Zgłoś uwagę" and "Wyloguj się" switches to the light theme and back ([ADR-0054](../decisions/0054-switch-to-the-light-theme-from-the-menu.md)). Views never set colours per theme: they use semantic tokens, which follow `data-theme` on `<html>`.
- Motion is short and functional: a panel that opens or closes, such as the side menu, or a toast that appears and fades, transitions over `--duration-short`. Every transition and animation sits inside `@media (prefers-reduced-motion: no-preference)`; Stylelint enforces this (`study-atelier/motion-needs-no-preference`), and lets through only values that move nothing, such as `none` or a `0s` animation that delays showing a loading indicator.

## Loading

- Something that loads shows it only after `--duration-loading-delay` (300 ms), so a fast load shows nothing. With reduced motion a loading indicator stands still. Why it looks this way: [ADR-0030](../decisions/0030-loading-states-for-the-first-load-and-images.md).
- The first app load is the full-screen `LoadingScreen`: the logo mark on the stage background, with one horizontal and one vertical stroke in its window. `hooks.server.ts` renders it into the page shell, `hooks.client.ts` takes it over, and the root layout removes it on its first mount.
- An image that loads is primed: `Primer` lays two coats of faint strokes across its window, horizontal then vertical, in the muted text colour of the surface.
- A navigation that is still loading shows a thin stroke travelling along the bottom edge of the top bar (the library `ProgressLine`, a `progressbar` named "Wczytywanie", placed by `AtelierLayout`), after the same 300 ms delay; the content is `aria-busy`. The back arrow of the artwork view and the forms does nothing while a navigation is in progress, so a second click cannot leave the app.
- A form's running state stays in its submit label ("Zapisywanie…"); it does not get a loading indicator. The same holds for a button that starts a review round, on the review start and in the summary: it reads "Przygotowywanie rundy…" and is disabled until the round shows.
- A fetch from an external source that fills form fields locks only the fields it may fill (empty or still holding fetched values) with `filling` on the library field: read-only and `aria-busy`, with its outline kept and its content covered by `FillingLines`, faint text-sized bars ([ADR-0151](../decisions/0151-show-a-filling-field-with-text-sized-lines.md)). `FillingStatus` names the fetch ("Wyszukiwanie w Wikipedii…") with "Przerwij", inside the bottom of a text area through `fillingNote` so nothing moves; "Przerwij" stops the fetch and unlocks the fields, and the form's submit is disabled until the fetch ends or is stopped. The fields that drive the search stay open, and changing them drops the running fetch. A search dialog primes its result area with the same line and no "Przerwij". Requests to Wikimedia give up after 10 s (15 s for the Wikidata query service), a whole search after 20 s and an image from an address after 15 s ([ADR-0150](../decisions/0150-lock-the-fields-an-external-fetch-fills.md)).
- On a phone a tile's image is at most the screen height minus the top bar tall (`--artwork-max-height`, set by `AtelierLayout` from `--bar-height` and `100dvh`, which follows the browser bars), keeping its proportions and centred in the tile, so at least one whole image fits on the screen. From 768 px the cap is off. The artwork view fits its image in a stage of a fixed height instead, so every artwork's first screen is the same ([ADR-0111](../decisions/0111-fixed-height-first-screen-of-an-artwork-on-a-phone.md)).
- A search over a list is the library `SearchField` in the top bar. It filters as the learner types, and its accessible name comes from `label` because the bar has no room for a visible label. It is at most `--size-content-default` wide. On the wall the controls of the top bar sit in one group as wide as the wall, in line with both of its edges also while the filter panel is open: the group sets margins of half the space left beside `--size-content-wide` and the panel, the one element allowed its own outer margins, and the search field takes the room the other controls leave (`flex: 1`). On a phone the placeholder of a `SearchField` is 14 px while the text typed stays 16 px, so more of it fits and iOS still does not zoom on focus. The wall's placeholder still does not fit there, so on a phone it is only "Szukaj", while `label` keeps the full "Szukaj po tytule lub autorze".
- On every tab of values the card index offers to add one in the same row as the search and the order, at the right ("Dodaj materiał", "Dodaj autora", "Dodaj miejsce", and "Dodaj okres" with "Dodaj styl" on the timeline tab), next to "Dodaj wydarzenie" on the events tab. It opens the value's edit form at `/atelier/values/<kind>/new`, titled "Nowy materiał", "Nowy autor" and so on; a name the kind already has is refused under the field ("Masz już autora „…”."), and the saved value opens its page with "Dodano … „…”.". The page of a list own field has a primary "Dodaj wartość" next to the search of its "Wartości", a small dialog with "Nazwa" only ([ADR-0158](../decisions/0158-add-values-straight-from-the-card-index.md)).
- Every list of the card index (the periods and styles, materials, authors, locations, events and the values of own lists) has its `SearchField` above the list instead of in the top bar, however few values it has, filling the row before the order and the add buttons (`CardIndexTools`). The order `Select` shows the `arrow-up-down` icon. Rows are separated by hairlines, the number of artworks is spelled out at the right ("2 dzieła"), and a hover tints the whole row with `--color-tag` instead of underlining the name. An icon after the name shows a place's type or whether an event is a single year (`circle-dot`) or a span (`move-horizontal`). The icon and the muted details after the name (a place's country) stand in one line with it, `--spacing-3` apart and as far from a line they wrap to; the icon, the details and the number of artworks are centred on the name's first line. An era's years stand after its name in an outlined badge ("3000 p.n.e. – 476") ([ADR-0188](../decisions/0188-redesign-the-card-index-lists.md)). It filters by name with `normalizeForSearch`, says so when nothing matches, and starts empty on every tab; in the timeline tab a matching style keeps its period and era, a matching period keeps all its styles, and an era without matches is left out.
- The timeline tab ("Okresy i style") keeps the eras along a vertical line, each a filled square with its icon, its name in the title font in italics as a link to its page and its years in an outlined badge (under the name on a phone, `--spacing-2` above the open list), and a chevron button at the right that folds the era. Periods are record rows like the other tabs, with a chevron button at the left that unfolds their styles (an empty room for a period without styles); styles are lighter, indented rows in regular weight with hairlines in `--color-tag`. At first every era is unfolded and every period folded; the folding is kept on the device (`timeline-folding.svelte.ts`), and while the learner searches, every era shown and every period with a matching style is unfolded without changing what is kept. "Okresy bez epoki" and "Style bez okresu" follow the axis under a hairline, with their headings in small capitals and the same rows ([ADR-0240](../decisions/0240-fold-eras-and-periods-in-the-timeline-tab-of-kartoteka.md)).
- Next to the search a `Select` without a visible label ("Sortuj") orders the list: "Według nazwy" (the default) and "Według liczby dzieł" (the most used first) on every tab but events, plus "Według lat życia" for authors (by the year of birth), "Według kraju" for places (by country, then name; a place shows its country next to its name in every order) and "Według daty" for events; values without a year or a country come last. In the timeline tab each level is sorted and the eras keep their order. The choice is kept on the device for each tab (`card-index-sort.ts`); on a phone the select stands under the search.
- The order of the wall is a `Select` with `compact`, `hideLabel` (the name stays for assistive technology) and an `icon` in the top bar, after the search field and before "Dodaj dzieło", shown from 768 px; on a phone the order is chosen in the view dialog ([ADR-0033](../decisions/0033-order-the-wall-by-period-with-a-period-rail.md)).
- The grouping of the wall is a `PopupButton` between the search field and the order. Its button shows three short lines set as steps, the chosen levels bright, and a tooltip names the grouping; the popover holds a `StepSelect` with `size="lg"` under "Grupuj", where a tile turns grouping on down to its level and the pressed deepest tile turns its level off. On a phone the same `StepSelect` sits in the "Widok" dialog under the order ([ADR-0085](../decisions/0085-group-the-wall-by-era-period-and-style.md)).
- A group with a heading and a count that can be collapsed is the library `Disclosure` (a native `details`), as in the review summary; with `lazy` it draws its content only while open, and with `plain` its title is a muted caption without a heading, as "Zmień zakres lub formę" on the review start.
- A main section of a page folds like a room of "Ekspozycja" and a section of "Statystyki": a `Disclosure` with `room`, a hairline in `--color-line` above it, its `h2` in the title font, in italics, at `--font-size-2xl` with its `Count` (which keeps the upright UI font), and the chevron at the end of the row. So do "Powiązania" and the artworks of a value page ("Dzieła tego autora") and an event page ("Dzieła z tego czasu"), "Widziane na żywo" of a visit, the years of Kronika (the first without its own line, right under the header's), and "Detale" and "Na dziełach" of a glossary entry.
- A side part of a page (the visits and exhibitions of an artwork, the notes and "Wspominasz o tym w notatkach" of an artwork or a value) is a muted `Disclosure` with an icon, its `h2` at `--font-size-md`: `footprints` for the visits, `landmark` for the exhibitions, `notebook-pen` for "Notatki" (`NotesSection`, open at first) and `at-sign` for the notes that link there (`MentionedIn`, with its count, closed at first, also as "Pojawia się w notatkach" of a glossary entry).
- The headings of the review start (the scope, the form, the side panel) keep their own style, `--font-size-md` (`ChoiceTitle`), because the room style would clash with the artwork titles under "Ostatnio sprawiały kłopot".
- A number in a small filled box (the count beside a section title, the reviews waiting next to "Powtórki") is the library `Count`. It has one style, filled and in the upright UI font, also beside a heading in the title font. A count written in a title's text ("Widziane na żywo · 1 wizyta", "Na 3 wystawach") stays part of the text. A muted number in a line of text, as in the periods and styles of the card index and the filter tiles, stays plain text. A grouped wall is a section per group, each a `Disclosure` with its own `ArtworkWall`: eras are `h2` with their icon and divided by a hairline in `--color-tag`, periods `h3`, styles `h4` muted. "Zwiń wszystkie" / "Rozwiń wszystkie" stands next to the count above the wall. All groups share one budget of tiles drawn 60 at a time, and a collapsed group draws nothing.
- While the wall is grouped, the current era is shown by the `PeriodRail` fixed to the right edge when the margin beside the wall is at least 128 px wide, and by the `PeriodStrip` sticky under the top bar when it is not. On the rail the line of a period leaves the bottom stack when the screen reaches its first artwork, travels up at the pace of the page and lands in the top stack after the distance it has to cover, however long the period is. The choice follows the measured margin, not a media query, because the side menu changes the margin. `AtelierLayout` publishes the bar's height as `--bar-height` for both.
- The rail measures a grouped wall from the section of each era, so an era starts where its heading is.
- While the wall is ordered by author without grouping, the same rail and strip show the authors, without an era icon. The rail names only the current author when its rows are shorter than 18 px, and the strip drops its marks when there are more than 12 blocks, so a long list of authors never overlaps or overflows.
- An icon button inside a field (show password, clear search) fills the field's height and is separated from the text by a hairline vertical divider.
- Every single-line control (`Button`, `TextField`, `Select`, `SearchField`, and `ValueField` while its values fit on one line) is `--size-control` high, so a button next to a field lines up without extra styling. A new control sets `min-height: var(--size-control)` on its outlined box and no vertical padding of its own.
- A button that acts on what was typed in one field (for example "Użyj" next to an image URL) is passed to `TextField` as its `action`, so it stands next to the input under the label and stays there when an error shows under the field.

## Text roles

`base.css` styles each role once. Views use the role and do not restyle it.

| Role                                        | Markup               | Look                    |
| ------------------------------------------- | -------------------- | ----------------------- |
| Page title                                  | `h1`                 | `xl`, bold              |
| Section title                               | `h2`                 | `lg`, bold              |
| Subsection title                            | `h3`                 | `md`, bold              |
| Minor title, for example a style group      | `h4`                 | `sm`, bold              |
| Lead, one sentence under the page title     | `p.lead`             | `md`, muted             |
| Body                                        | `p`                  | `md`                    |
| Caption: metadata, hints, secondary details | `.caption`           | `sm`, muted             |
| Overline: the kind above a title, a label   | `.overline`          | `sm`, small caps, muted |
| Artwork title                               | `cite.artwork-title` | Newsreader italic, `lg` |

- Every page has one `h1`. The page title in the browser tab is built with `m.app.pageTitle(title)`.
- A line of short details separated by "·" (the author and the year under a title, the number of artworks and the date on an exhibition card, the kind line above a value's name) is the library `MetaLine`: one spacing (`--spacing-2`) on each side of the "·", which is hidden from screen readers. It takes the parts, empty ones left out, or a dictionary text that it splits at " · ". A line cut with an ellipsis (a quiz tile's caption) stays plain text.
- The values right under the title of a detail page (the years of an author's life, the type and the country of a place, an era's years, the date of an event) are body text, not a muted caption, so they read as part of the page's subject.
- An overline (the kind above a title, "Wystawa", "Autor · 3 dzieła", the label of a review question such as "Odgadnij datę powstania", a group in the relations band) is `.overline` from `base.css`: small capitals in `--color-fg-muted`, never upper case.
- Newsreader is used only for artwork titles and, by the owner's decision, for the learner's rank in the menu and the display case and the tier numeral on an exhibit.

## Element defaults

- The default look of HTML elements (links, headings, paragraphs, focus outline) lives only in `packages/ui/src/lib/styles/base.css`.
- Text for screen readers only has the global class `visually-hidden` from `base.css`; a component never copies its rules. When the text hides only in one state, the class is toggled with `class:visually-hidden`, and a library component whose label can be hidden takes a prop for it (`labelHidden` of `ValueField`, `hideLabel` of `Select`).
- A style that two or more views repeat moves into a library component or `base.css`.
- Library controls build on native HTML elements (`dialog`, `select`, `input`), which bring their behaviour, accessibility and the phone's own pickers. Their look comes from tokens. Styling that only some browsers support (for example `appearance: base-select`) sits inside `@supports`, so the other browsers keep the plain native look.
- `PopupButton` opens a panel under its button: a `button` with `aria-expanded` and a `div` of role `dialog` named like the button. It closes on a second click, a click outside or Escape, which gives the focus back to the button; a choice inside does not close it. With `bare` its button has no look of its own, only its trigger (the lamps of the display case), and the panel opens under the nearest positioned container, so a row of small marks shares one place for its panels. With `placement="top"` the panel opens above its button, and with `placement="auto"` (the lamps) it opens below and turns above when the screen has no room for it below but has room above, so a panel in the last row does not stretch the page. With `hover` it also opens while a mouse is over it and closes when it leaves, a click keeping it open; a `Tooltip` and a panel opened on hover appear the same way, after twice `--duration-short` and fading in over `--duration-short` (`--hover-reveal-delay` in the library's `base.css` and a `hover-reveal` fade in each component, only without reduced motion); `placement="top"` opens the panel above the button, at the bottom of a page.
- The suggestion lists of `ValueField`, `SearchSelect` and the notes editor (`NoteLinkList`) open under their field and stand above a `FormActions` bar. With the `dropPlacement` attachment, a list that has no room between the field and the bar (or the bottom of the visible screen, with an on-screen keyboard) opens upwards when there is more room above, and is cut to the room of the side it takes, so it never makes the page longer. A field that already reaches under the bar counts the bar too. When neither side has 120 px, the list lies over its field at the bottom of the visible area, above the bar. Inside a scrolled container or a dialog the list stays within it, and it is placed again on every scroll, also of the visible area with an on-screen keyboard.
- The one exception is `NotesEditor`: a `contenteditable` region driven by TipTap, because formatted notes cannot be edited in a native element ([ADR-0029](../decisions/0029-format-notes-with-a-visual-markdown-editor.md)). It keeps the `TextArea` look and exposes `role="textbox"` and a labelled `role="toolbar"`. Its links to values and artworks (`@`, `#`) are single tokens with a thin muted underline, and their suggestion list sits under the field like a value field's list ([ADR-0053](../decisions/0053-link-values-and-artworks-from-notes.md)).

## Links and buttons

- Going to another page is always a link, `<a href>`. SvelteKit's router handles internal links without a page reload. It preloads a page's code when the pointer rests on its link and the page's data only when the link is pressed, so moving the pointer across the wall sends nothing to the database ([ADR-0081](../decisions/0081-preload-page-data-on-tap.md)). A link that should look like a button is `<Button href={...}>`.
- `Button` without `href` is for actions on the current page: submit a form, sign out, resend a message.
- `goto` is for navigation from code after an action, for example after a successful sign-in. ESLint reports a `goto` called straight from an `onclick`.
- Each view has at most one `primary` button.
- The controls of one toolbar (a row of a search, an order or other fields with buttons, such as `WallTools`, `CardIndexTools` and the tools of the glossary list) share one text size: their `SearchField` and `Select` take `compact`, which sets their text to the 14 px of a `Button` from 768 px and keeps 16 px on a phone, so iOS does not zoom into a focused field. Fields of a form keep 16 px. On a phone the controls of one toolbar take the full width alike: a field that fills the row is matched by buttons that share the row below in equal columns, not narrow buttons at its start.
- Text cut with an ellipsis shows its full content in the library `Tooltip`, on hover and on keyboard focus, and only when it is actually cut.
- A `Tooltip` opens on hover and on keyboard focus (`:focus-visible`), not after a click, so a clicked button does not keep its tooltip; it stays hidden while its control has a panel open (`aria-expanded="true"`). On hover it fades in after 320 ms, so a pointer passing by shows nothing; on keyboard focus it fades in at once, and it goes the moment the pointer or focus leaves.
- A button in the top bar of the wall that has only an icon ("Filtry", the grouping) has its name in `aria-label` and the same text in a `Tooltip` with `placement="bottom"` and `align="end"`. "Filtry" is `primary` while a filter is on.
- A small action that reads as part of a line of text ("Wyczyść filtry", "Zwiń wszystkie") is the library `TextButton`: small, underlined, without a frame.
- A text action that stands in a column of left-aligned texts (in a card, a form, under a field) is a `TextButton` with `inline`, which drops the inline padding, so it lines up with the texts above and below it. A plain `TextButton` keeps its padding and belongs in a row of actions.
- A short note about something on the screen with more than one line of text (a value's summary in the artwork view) is a `Popover`: its trigger is a button that looks like the text or tag it wraps, the card opens on a click or a tap and, on a computer, also on hover (after `--hover-reveal-delay`, the 320 ms of a `Tooltip`, so a pointer passing by opens nothing) and at once on keyboard focus, and closes on a second click, a click elsewhere or Escape. Every hover card of `PopoverState` (a `Popover`, the glossary terms in notes, the pins of an image) waits this one delay, also when the pointer moves to another trigger while a card is open, so it can cross neighbouring pins or terms; a pointer that leaves before the delay opens nothing. Hover counts only on the trigger, and the card holds nothing to click and lets clicks through, so it never covers other triggers ([ADR-0059](../decisions/0059-value-summary-card-in-the-artwork-view.md)). A card that does not fit to the right of its trigger opens to the left, and the room is measured without the scrollbar ([ADR-0077](../decisions/0077-trim-the-wikipedia-lead-and-polish-the-glossary-list.md)). A plain `Tooltip` stays for one short line.
- Glossary terms in read-only notes are `button`s inside the `Notes` text with the background of a tag; they open the same card as a `Popover` (`PopoverState` and `PopoverCard` are shared), with the entry's category, name, definition and source. The views mark terms from a light index of the glossary kept in the data cache (names, synonyms, forms, category and whether there is a definition); the card is rendered only while it is open, loads the definition and source of its one term by id the first time it opens, shows "Wczytuję definicję…" in the space of about three lines meanwhile, says so when the load fails (the next opening tries again) or the entry was deleted, and is placed again when its content changes. Only the first occurrence of an entry in a note is marked, and the editor shows notes unmarked ([ADR-0074](../decisions/0074-keep-a-glossary-of-terms-with-definitions-from-wikipedia.md)). Terms are also marked in the definition on an entry's page (`Notes` with `plain`, which reads the text without Markdown and never marks the entry itself) and in the notes of a revealed review flashcard ([ADR-0079](../decisions/0079-connect-the-lexicon-and-suggest-forms-from-wiktionary.md)).
- The card of a term ends, after a hairline, with the link "Otwórz w Słowniczku" (`arrow-right`) to the entry's page, so unlike other cards it can be clicked (`interactive` on `Notes` and `PopoverCard`): it is a non-modal `dialog` named by the marked word, it stays open while the pointer moves from the word onto it and closes 120 ms after the pointer leaves both, and a click inside it does not close it. Tab from the word moves into the card, Tab from its last link on to what follows the word, Shift+Tab back to the word, and Escape closes it and returns the focus to the word. On a phone the first tap on the word opens the card and a tap on the link opens the page. On a review flashcard the card has no link and stays a `tooltip` like any other, so it is no way out of the session.
- Details with actions of their own about an item on a stage (a timeline event) open in an interactive `PopoverCard` driven by a `PopoverState`, on a click or Enter only, never on hover. It stays open until Escape, a click outside or an action in it; an action closes it first and gives the focus back to the item, so a dialog it opens returns there too. Its `boundary` keeps it sideways within the stage ([ADR-0241](../decisions/0241-show-a-timeline-event-in-a-popover-and-drop-the-artworks-at-the-reading-line.md)).
- A `Tooltip` opens above its control and grows from the control's start. A control at the top or right edge of the screen, such as a button at the end of the top bar, uses `placement="bottom"` and `align="end"` so the bubble stays inside the viewport.
- The actions on one item of a list that are not its main action sit in a `PopupButton` with the Lucide `ellipsis` icon and `align="end"`, named after the item ("Działania pola „Wykład”"). Its items are `TextButton`s in a column, the delete one with `danger`, and an item that cannot apply is disabled. A choice calls the popup's `close()` first, so the focus goes back to the "…" button and a dialog the choice opens returns the focus there ([ADR-0104](../decisions/0104-let-the-learner-define-own-artwork-fields.md)).
- Sign out is shown in `--color-danger`, so it stands apart from the menu items that navigate.
- A button that deletes is `variant="danger"`: an outline and text in `--color-danger`. The button that confirms the delete in its dialog stays `primary`.
- Red (`--color-danger`) marks only an action that loses data or signs out: "Usuń" in a top bar, "Usuń obraz", "Usuń portret" and "Usuń zdjęcie" under an image, "Usuń źródło" (a `TextButton` with `danger`), the remove button of a block's toolbar in the exhibition editor, "Wyloguj się". An action that can be undone at once (change, pick another, move, hide) is never red.
- An image that belongs to a form (an artwork's image, an author's portrait, the avatar in Ustawienia › Profil) has its actions as text buttons with an icon under the picture: finding an image ("Znajdź obraz", "Wybierz inny") is `primary`, adding or changing an own one is secondary, and removing it is `danger`.

## Messages

- `Alert` shows status: `danger` for errors, `warning` for something to check, `success` for a finished action. Its label (`BŁĄD`, `UWAGA`, `GOTOWE`) comes from the shared library texts, so views do not pass it.
- An error that belongs to one field is shown under the field (`TextField` `error`).
- An error that belongs to the whole form is an `Alert` at the top of the form, with a title that names what failed ("Nie udało się zalogować"). When a save fails, the form scrolls the `Alert` into view, because the learner pressed Save further down The library `Form` does both: it takes the message as `error` and the title as `errorTitle`, renders the `Alert` as its first child and scrolls it into view when it appears.
- When a write fails because the session is no longer valid, the learner is signed out and the sign-in page opens with a warning `Alert` ("Twoja sesja wygasła").
- A success that ends the task replaces the form with an `Alert`. A success that keeps the user on the same task stands above the action it confirms.
- A short confirmation that must not move the layout is a `Toast`, for example "Zapisano dzieło #0012." after "Zapisz i dodaj kolejne" empties the form for the next artwork. It floats above the content, centred, at most `--size-content-narrow` wide from 768 px and full width with side gutters on a phone. It appears after a half-beat delay with a short rise, disappears after 5 seconds, waits while a mouse pointer is over it and goes within a second once it leaves (a tap on a touch screen leaves its time as it was), and has no close button. A new message replaces the one on screen.
- A view places one `Toast` and calls its `show(text)`. On a page with an action bar fixed to the bottom, the view passes the bar's height as `offset`, so the toast stands 16 px above the bar; above the bottom bar of a phone it stands by itself, through `--bottom-inset`.
- A new release of the app is announced by `NewVersionNotice` in `AtelierLayout`: "Pojawiła się nowa wersja aplikacji. Odśwież stronę, żeby z niej skorzystać." with "Odśwież". It looks like a toast and stands where one would, above the `FormActions` bar of a form, but stays until the page reloads. The next navigation in the app loads the page from the server; a form with unsaved changes still asks "Odrzucić zmiany?" first, and "Odśwież" leaves it only after the browser's own question ([ADR-0139](../decisions/0139-ask-the-learner-to-reload-after-a-new-release.md)).
- An announcement from the owner stands under the top bar of the atelier, aligned with the content, as a `warning` `Alert` labelled "Komunikat" with the announcement's title and text, and "Zamknij" (a `TextButton` named "Zamknij komunikat") under its right edge ([ADR-0145](../decisions/0145-show-announcements-from-a-table.md)).
- Errors and warnings are never toasts: they stay in an `Alert` or under the field until the learner acts on them, because a toast can disappear before it is read.
- Raw errors from Supabase or other services are never shown; they are mapped to dictionary messages (see [code-conventions.md](code-conventions.md#errors-from-services)).
- A view with nothing to show yet uses the library `EmptyState`, centred in the content with generous space around it ([ADR-0130](../decisions/0130-show-empty-views-in-one-centred-pattern.md)). A whole empty module (Atelier, Słowniczek, Kronika, Kalendarium without dated artworks and events, Archiwum, and Powtórki before there are enough artworks) passes a `title` ("Słowniczek jest jeszcze pusty"), a few sentences on what the module is for and how it fills up, and its first action as a secondary `Button` with `Plus` ("Dodaj pierwsze pojęcie"), repeated from the top bar because on a phone the bar shows only the icon; Archiwum has no action. The empty Atelier is the learner's first view, so `WallWelcome` adds "Jak to działa?" under it: three numbered steps ("Dodaj dzieło", "Opisuj i łącz", "Powtarzaj") side by side from 768 px and one under another on a phone, each an `h3` with a body paragraph. It disappears with the first artwork, so nothing is dismissed or stored ([ADR-0143](../decisions/0143-welcome-a-new-learner-on-the-empty-wall.md)). An empty part of a page (a tab of the card index) passes no title: a smaller icon and one or two muted sentences, with the tab's own action staying above the list. The icon is the module's icon from the menu. An empty structure is not drawn: the periods and styles tab draws no eras while no era has a period, and Kalendarium without anything dated shows only the empty state, while an era without periods among others, or the events lane beside dated artworks, keeps a short line (on a phone above the stage, never turned sideways). The "nothing matches" states of a search or a filter are separate and keep their own messages.

## Forms

- A form is the library `Form`: it turns off browser validation, prevents the page reload and, after submit, moves focus to the first field marked invalid and scrolls it to the middle of the screen, so a sticky bar never hides it.
- Fields are `TextField`, `TextArea` (longer plain text; with `counter` and `maxlength` it shows the count on the right under the field, red at the limit; `maxRows` caps how tall the learner can drag it, eight lines for the summary of a value), `NotesEditor` (formatted notes, [ADR-0029](../decisions/0029-format-notes-with-a-visual-markdown-editor.md)), `Checkbox` and future library inputs, each with a visible label and the right `autocomplete` value.
- A single choice from a short fixed list that the learner should see all at once (the era) is `ChoiceTiles`: one row of tiles, three by two when the field is narrower than 600 px, each with an optional icon above the name, which may wrap to two lines, and a note under it that never wraps (the type of place uses tiles with icons and no notes). A longer list sets `columns` and `narrowColumns`: the artwork type has eight tiles in four columns at every width ([ADR-0066](../decisions/0066-icons-for-artwork-types-shown-like-eras.md), [ADR-0252](../decisions/0252-overhaul-the-app-on-a-phone.md)). Tiles of four columns or more narrower than 600 px set their names at `--font-size-xs`, so a name such as "Architektura" fits its tile. It is a native radio group, so the arrow keys move the choice. When the choice is optional the app sets `clearable` and clicking the chosen tile, or pressing the space bar on it, clears it. The chosen tile is filled like a primary button ([ADR-0038](../decisions/0038-chain-era-period-and-style.md)).
- A single choice from a long fixed list (the countries) is a `SearchSelect`: the learner types part of the name and picks from the filtered list; it holds the code ([ADR-0057](../decisions/0057-location-country-and-type-of-place.md)).
- A single choice from a longer fixed list is a `Select`, with an empty first option such as "Nie wybrano" passed as `placeholder` when the field is optional.
- A category value (authors, period, style, material, location) is a `ValueField`: the chosen values are tags inside the field, and the suggestion list under it shows what the app passes as `options`. Which values to suggest, and whether a new value may be created, is decided in the app, not in the component. An option can carry a note (the country of a place), shown small on the right, and the `starter` kind is listed in a group of its own after the values in use.
- A field that depends on the one above it (Okres on the era, Styl on the Okres) is a `ValueField` with `locked` until that field is filled; the reason is its placeholder ("Najpierw wybierz epokę."). A locked field looks disabled but, when it still holds a value, lets the learner remove it. The fields below are cleared when the one above changes or is cleared, but not when it is first filled in.
- A setting that governs the fields below it is a `Switch` (a native checkbox with `role="switch"`, square, label first), placed above those fields on the right of the label row, together with any option that applies to all of them. The date of creation and the years of life of an author (`YearGroup` with `YearInput`) are the examples. In the date of creation "ok." and the switch "Od – do" stand beside the title of the field, and the "p.n.e." of each year stays under its input. A group of inputs that share one title hides their individual labels (`TextField` `hideLabel`: the name stays for assistive technology and the placeholder says which is which, for example "Od" and "Do"), and the group is named by the title with `role="group"` ([ADR-0046](../decisions/0046-enter-the-date-of-creation-as-a-year-span.md)).
- A disabled field looks the same in every library input: a flat `--color-tag` fill instead of the outline, with the label and the text in `--color-fg-muted`.
- After a value is picked in a `ValueField` that takes many values, the suggestion list stays open for the next one. Removing a value with the mouse leaves focus where it was; with the keyboard, focus moves to the next remove button, or to the field without opening the list. In a `ValueField` that takes one value, picking with the mouse or a finger leaves focus alone, so the remove button shows no focus ring; picking with the keyboard moves focus to the remove button.
- On a phone, form fields take the full content width, and so do an image that belongs to the form and the buttons under it.
- The artwork form starts with "Tytuł" and "Autorzy", which a museum label gives and which start the automatic image match: on a phone above the images, from 768 px at the top of the right column beside them. On a phone its empty image frame, and the primed frame while a match is searched, are 140 px high, and the frame takes the proportions of the image once one is shown ([ADR-0252](../decisions/0252-overhaul-the-app-on-a-phone.md)). `NoImage` with `fill` takes the height of its container there.
- The flow on submit:
  1. Validate every field and clear the form error.
  2. If a field is invalid, stop. Its error shows under it and focus moves to the first invalid field.
  3. Disable the submit button and switch its label to the running form ("Logowanie…", with the single `…` character).
  4. Call the domain function from `#lib/<domain>`.
  5. On failure, show the mapped message in the form `Alert` and enable the button again.
  6. On success, navigate with `goto` or replace the form with a success `Alert`.
- In the app the flow runs through `FormState` (`#lib/shared/forms/form-state/form-state.svelte.ts`): it holds `busy`, the form `error` and the `saved` snapshot that `UnsavedChanges` compares with, and `run(save)` clears the error, sets `busy` for the time of the save and ignores a second submit while one is running. The form passes `formState.error` to `Form`. Field errors come from `LiveErrors` (`#lib/shared/forms/live-errors/live-errors.svelte.ts`): they show first on a save (`check()`), and after a failed save every change checks the form again, so a corrected field loses its error at once and a field still wrong keeps it; an error only the database knows (a name already taken) is added with `add()` and goes when its field changes.
- Fields are validated on submit, not while typing.
- A long form keeps its actions in the library `FormActions`, a bar fixed to the bottom of the screen; a short form fills the screen so the bar still sits at the bottom. The bar has the `--color-surface` background and spans the whole content column, to the screen edges on a phone (`AtelierLayout` sets `--form-actions-bleed` and drops the space under the content of a page with the bar, and a `Tabs` panel that holds the bar draws no frame of its own, so the bar stays at the bottom edge also at the end of the page). In the settings the app's `SettingsForm` frames the tab's content as a card that ends under the content, and the bar stands below it at the bottom of the screen; at the end of a long tab the card's bottom edge shows above the bar ([ADR-0244](../decisions/0244-frame-a-settings-tab-under-its-content-above-the-save-bar.md)). On a phone the actions stand in one row: "Anuluj" keeps its own width and the save actions share the rest. The action that leaves without saving ("Anuluj") is a link back to where the learner came from.
- A form that holds work the learner could lose asks before the learner leaves it, by any navigation inside the app or by signing out: a small `Dialog` "Odrzucić zmiany?" with "Wróć do formularza" and "Odrzuć". Without changes it lets the learner leave without asking. Closing the tab shows the browser's own warning, whose text the app cannot set. In the app this is `UnsavedChanges` (`#lib/shared/forms/unsaved-changes/unsaved-changes.svelte.ts`) with `DiscardDialog`; the form passes how to read its state and how to compare two states.
- Limits used by a validator (for example `MIN_PASSWORD_LENGTH`) are exported constants, and the field hint uses the same constant.
- The learner's own fields follow the built-in ones in the artwork form, after "Miejsce" and before "Notatki": a text is a `TextField`, a list a `ValueField` like a category value, and "Zaznaczenie" a `Checkbox` whose description is a `FieldMessage` linked by `aria-describedby`. The field's description is its hint. In the artwork view they follow "Miejsce": the values of a list as tags without a summary card, a text and a tick as plain text, empty and unticked ones left out. In Kartoteka the tab "Własne pola" lists the fields as rows like the other tabs (name, kind, the icons of its types, the number of artworks), each a link to the field's page at `/atelier/fields/<id>`. "Zmień kolejność" turns the rows into a mode with an up and a down `IconButton` per row and "Gotowe" to leave it; the order is the order of the artwork form. The field's page has the kind line ("Własne pole · Lista, kilka wartości · 4 dzieła"), the name, the description, "Dotyczy dzieł typu" with outlined badges or "Wszystkie typy", and for a list the section "Wartości" with the values as rows; "Edytuj" opens the field form and "Usuń" asks first. A value has its page at `/atelier/fields/<id>/values/<value id>` with the artworks that have it, and "Edytuj" renames it or merges it into another value of the field after a confirmation ([ADR-0189](../decisions/0189-scope-own-fields-to-artwork-types-and-give-them-pages.md)). A field can be limited to chosen artwork types: the field form has a `Checkbox` "Tylko dla wybranych typów dzieł" that reveals the type `ToggleTiles` and scrolls the dialog so they come into view (smoothly unless the learner prefers reduced motion), the form of an artwork shows only the fields that apply to its type (an artwork without a type only the fields for all types), Kartoteka shows the icons of the types after the field's name, and saving an artwork whose new type drops filled fields, or a field narrowed to fewer types, first asks and names what gets deleted ([ADR-0189](../decisions/0189-scope-own-fields-to-artwork-types-and-give-them-pages.md)).
- A sentence that says what to write in a field is its placeholder, as in "Notatki" ("Wszystko, co warto zapamiętać") and "Podsumowanie". A hint under the field is kept for a rule or a consequence the learner must know, such as a limit or where a value is used.

## Dialogs

- A dialog is the library `Dialog`: a modal over `--color-scrim`, with the page behind it blurred by `--blur-scrim` (inside `@supports`, so other browsers keep the plain scrim), that keeps focus inside, stops the page behind it from scrolling, closes with Escape and returns focus to the element that opened it. The view controls it with `bind:open`.
- The default size is for a task inside the dialog, such as picking an image candidate. It has a close button, takes the full screen on a phone and is at most `--size-content-default` wide from 768 px. Its actions sit in the `footer` snippet.
- `size="wide"` is the default size up to 960 px wide from 768 px, for a choice among many pictures, such as the pins of an artwork in the exhibition editor.
- `size="small"` is for a confirmation such as "Odrzucić zmiany?": a short question as the title, the consequence as the `description`, and two buttons in the footer, the safe one first and the one that confirms as `primary`. It has no close button; Escape answers with the safe choice.
- A dialog that edits one item of a list is the default size: the item's name as the title, its kind and use as the `description`, its fields in the body, and in the footer the danger action on the left with the safe and the primary action on the right. A change that touches other records, such as merging two values, asks again in a small `Dialog` that names how many records change ([ADR-0040](../decisions/0040-manage-category-values-in-a-card-index.md)). An item with long text, such as a category value with its notes, is edited in a form on its own page like an artwork instead ([ADR-0049](../decisions/0049-give-every-category-value-a-page-of-its-own.md)).
- A dialog does not close when the learner clicks the scrim, so a choice is never lost by a stray click.
- Questions on saving an artwork come one at a time in a fixed order: the year outside its era (`EraDialog`, [ADR-0176](../decisions/0176-ask-before-saving-a-year-outside-its-era.md)) before a duplicate title (`DuplicateDialog`); going back from one ends the save.

## Filters

- The wall's filters follow [ADR-0042](../decisions/0042-filter-the-collection-in-the-browser.md). A choice of several values from a fixed list (the eras, and the artwork types in two columns through `columns`) is `ToggleTiles`: the tiles of `ChoiceTiles` as native checkboxes, each with an optional count. A fixed list shows every value, also those with 0, and has no search field. A choice of several values from a list that grows with the learner's data is a row of `ToggleTag` buttons: a tag that is pressed (`aria-pressed`) when chosen and shows the number of artworks next to it.
- On a larger screen the filters open in a side panel at the right edge, under the top bar, that takes the free side margins of the content first and narrows the wall only when they run out, and changes it at once. It opens and closes with the same width animation as the side menu, off under `prefers-reduced-motion`. On a phone the order and the filters share a full-screen `Dialog` ("Widok") that closes with a button naming the number of artworks left.
- A side panel at the right edge ("Informacje" in the artwork view, "Filtry" on the wall and in Kalendarium, "Przybornik" in the exhibition editor) starts with the library `PanelHeader`: its name in the look of a section title (`lg`, bold) and a button that folds the panel, with the Lucide `panel-right-close` icon, named "Zwiń …" and showing that name in a `Tooltip`. The panel folds, it does not close, so the button never shows `x`.
- The filter panel ends with "Wyczyść filtry" as an `inline` `TextButton`, disabled while no filter is on, and shows no count: the count stands over the wall. "Pokaż mniej" scrolls the heading of its list back into view, and a value too long for one line is cut with an ellipsis, with its whole name in `title`. A subsection of a filter section ("Okresy" and "Style" under "Okresy i style" in Kalendarium) is named in small capitals in `--color-fg-muted` (`--font-size-xs`, `--letter-spacing-wide`), like a field name in a tag.
- Own fields follow "Miejsce" in the panel: a list as `ToggleTag`s like a category value, a text as a compact `SearchField` under its name, and the ticks together in a section "Zaznaczone" ([ADR-0105](../decisions/0105-filter-the-wall-by-own-fields.md)). Once artwork types are chosen, only the own fields of those types and the fields for all types are offered, plus any field still filtered by ([ADR-0189](../decisions/0189-scope-own-fields-to-artwork-types-and-give-them-pages.md)).
- Active filters sit above the wall as `Tag`s with a remove button, followed by a text button that clears them all. In a tag the field name is small capitals in `--color-fg-muted` (`--font-size-xs`, `--letter-spacing-wide`) and the value is regular text, so "Typ Rzeźba" reads as a field and its value at a glance.
- On a larger screen nothing reserves room for a scrollbar: the page has the library `PageScrollbar`, and every element that scrolls on its own takes `{@attach overlayScrollbar()}` (`'x'` for a row such as the tabs). The native bar is hidden and a square thumb is drawn over the content, `--size-scrollbar-rest` wide in `--color-fg-muted`, `--size-scrollbar-active` and `--color-fg` on hover and drag; it shows while scrolling and on hover and fades after a pause. A panel at the window's right edge keeps its thumb inside the page's. Touch screens and forced colours keep the native bars ([ADR-0099](../decisions/0099-draw-an-overlay-scrollbar-on-a-larger-screen.md)).

## Tabs

- A hairline that divides a list or a view into sections runs across the whole width of the content, like the line under the `Tabs` of the card index; the text between the lines keeps its own width (for example `--size-content-default`).
- Kinds of one list or parts of one view that share a view are shown with the library `Tabs`, with `tablist` roles, the arrow keys, Home and End. Its boxed tabs are the one tab style of the app (Kartoteka, Archiwum, "Na pierwszym planie" in Statystyki, Ustawienia): the selected tab is a card-file divider joined to a framed panel that holds everything the tab shows, such as the search, the order, the add buttons (primary) and the list of Kartoteka, so the search does not look like it searches the whole view; the selected tab scrolls into view in a narrow row, which scrolls sideways on a phone ([ADR-0188](../decisions/0188-redesign-the-card-index-lists.md)). There is no underlined variant. A tab changes only what the view lists; it does not change the address. A tab that is not one more kind of the list ("Własne pola" in Kartoteka) takes `end` and stands apart at the right edge. On a phone the tabs lose the box: they stand in a row from edge to edge that scrolls sideways, the selected one marked by a `--border-width-button` line under it, and the panel has no frame, so the lists get the whole width; the card index tools stand in one row there, the order as its icon (`iconOnPhone`) and the add buttons as `plus` alone, with one `plus` on "Okresy i style" that offers "Dodaj okres" and "Dodaj styl" in a `PopupButton` ([ADR-0252](../decisions/0252-overhaul-the-app-on-a-phone.md)).
- A tag whose removal is not allowed is a `Tag` with `removeDisabled`, and the reason is written under the tags.

## Global shortcuts

- A keyboard shortcut that works anywhere in a view never takes over a text field. When the focus is in an `input`, a `textarea`, a `select` or an editable element such as the notes editor, the browser's own behaviour wins, even when the shortcut would otherwise apply to what the learner is doing.
- A shortcut is not the only way to a function: the same action has a visible control, because a phone has no keyboard.
- When a shortcut is mentioned in the interface, the keys are shown for the learner's system (⌘ on a Mac, Ctrl elsewhere).

## Artwork images

- An artwork image sits in `Frame`: `list` in lists, `view` in a detail view or on a stage. The image keeps its proportions and never fills a thumbnail slot at the side. The exception is the trash list, where the thumbnail is cropped to 4:5 on the paper passe-partout, so every row has the same height ([ADR-0028](../decisions/0028-trash-as-a-list-with-confirmed-deletes.md)). The image slots of the form and the thumbnails under the stage of the artwork page are also cropped, to squares, so a row of images stays even.
- The artwork page shows the main image on the stage. When the artwork has more images, a row of square thumbnails pinned to the bottom of the stage, `--spacing-6` above its edge ("Zdjęcie {n} z {m}", the shown one pressed), puts another image on the stage without the row moving, and the full-screen viewer steps through all of them with arrows at its sides and the arrow keys ([ADR-0088](../decisions/0088-up-to-five-images-and-an-automatic-best-match.md)).
- The controls of the shown image sit together in the top right corner of the stage as quiet icons in `--color-stage-fg`, semi-transparent until hover, focus or while they are on: the palette ("Paleta barw", `blend`, on any screen), the loupe ("Lupa", `search`, only with a mouse) and then the pins (`pin` with their number, only when the image has pins). An icon that cannot act stays dimmed with `aria-disabled` and gives the reason in its `Tooltip` ([ADR-0112](../decisions/0112-edit-pins-in-the-artwork-form.md), [ADR-0113](../decisions/0113-switch-the-loupe-on-from-the-corner-of-the-stage.md)).
- The palette is a band over the bottom of the image, inside the passe-partout, on a new semantic token `--color-palette-band` (the background at 85%) with `--spacing-3` of padding: a strip of segments as wide as their share and the hex code in `--font-size-xs` `--color-fg-muted` under a colour over 20% ([ADR-0203](../decisions/0203-show-the-palette-on-the-stage-and-compare-two-artworks-side-by-side.md)).
- The loupe is a circle of 220 px drawn with `clip-path` and an SVG ring in `--color-mat-bg`, with its level on a badge (`--color-mat-badge-*`). It covers the image while it is on, so a click on the image does nothing, and the cursor over the image is hidden ([ADR-0110](../decisions/0110-look-at-details-through-a-loupe.md)). Escape, a right click on the image (without the browser's menu) or a left click anywhere beside the image switches it off; a click on its icon or inside a dialog does not, and while it is on the icon's tooltip reads "Wyłącz lupę: Esc, prawy przycisk albo kliknięcie obok" ([ADR-0156](../decisions/0156-leave-the-loupe-with-a-right-click-or-a-click-beside-the-image.md)).
- A click with the loupe on opens "Nowa pinezka" with the view of the loupe in a circle above the fields, captioned "Widok lupy (n×)". The marker of a pin with a view has a small `--color-highlight` square in its top right corner, and its name ends with ", widok lupy". A view is drawn by the same lens as the loupe (`LoupeLens`), at most 220 px and narrower when its container is, centred in the pin card and in the dialog ([ADR-0114](../decisions/0114-keep-a-view-of-the-loupe-in-a-pin.md)). Until its image has loaded the lens shows the `Primer` in place of the picture, so a view never appears as a blank or half-loaded circle; a container that is not on screen (the hidden pin popover) does not make the lens smaller.
- Every artwork image is the library `ArtworkImage`, with the image's stored width and height. It holds the image's place until it loads, primes the window while it loads, tries once more after 3 seconds when it fails, and then shows "Nie udało się wczytać obrazu" with the `image-off` icon. Pass `surface="frame"` inside a `Frame` and `surface="stage"` directly on the stage, such as the full-screen view; the default is the paper passe-partout. A view styles the image through `:global(img)` inside its own container. A decorative copy of an image (a blurred backdrop) and the small cropped thumbnails of the trash list stay a plain `img`.
- In the collection each artwork is an `ArtworkTile`: the image on a solid paper passe-partout, 8 px on the top and sides, with the title, authors and date on the wider bottom edge the record number in the top right corner of the image and the icon of the artwork's era in the top left corner. Each sits on its own translucent badge, and the icon badge keeps vertical padding (`--spacing-1`) so it never touches the badge edge. The passe-partout is paper in the dark theme and a lighter card than the wall in the light theme (`--color-mat-*`), so it never disappears on the wall ([ADR-0054](../decisions/0054-switch-to-the-light-theme-from-the-menu.md)).
- The favourite heart ([ADR-0058](../decisions/0058-mark-artworks-as-favourites-with-a-heart.md)) is a button, never a part of the tile's link: on a tile it sits at the right end of the caption band, 16 px in `--color-mat-fg-muted` inside a `--size-control` touch area, an outline when off and filled when on, always visible; in the top bar of the artwork view it is an icon-only `Button` before "Edytuj". Both carry `aria-pressed` and the name "Dodaj do ulubionych" or "Usuń z ulubionych". Each change shows a `Toast` ("Dodano do ulubionych.", "Usunięto z ulubionych."); a failed save puts the heart back and shows an `Alert` at the top of the view. The filter panel starts with an "Ulubione" `ToggleTag` with a heart and the count, without a heading.
- An artwork without an image shows the library `NoImage` in the place of the image: the 4:5 window on `--color-mat-window` with a hairline rectangle inset by `--spacing-6` and both of its diagonals, drawn in `--color-mat-fg-muted` at reduced opacity, like the cross a catalogue prints for a picture without a photograph. It has no visible text and the accessible name "Brak obrazu". The wall tile, the stage of the artwork view (above "Dodaj obraz") and the image field of the form use it, so they never draw their own empty window. It is not the loading state, which is the primed window ([ADR-0034](../decisions/0034-catalogue-cross-for-artworks-without-an-image.md)). An artwork whose own image exists but could not be fetched is not an artwork without an image: its tile shows the failed state of `ArtworkImage` (the image-off icon and the text "Nie udało się wczytać obrazu", the same as for an image that did not load) instead of the cross, and the wall offers one retry above it.
- Every artwork goes to the shortest column, and its tile caption keeps its natural height. Wide artworks that span two columns from three columns up, with a caption of fixed height and a `Tooltip` for a cut one, are designed in [ADR-0035](../decisions/0035-wide-artworks-span-two-wall-columns.md) but not built yet ([ATL-84](https://linear.app/kamil-nawrot/issue/ATL-84/build-wide-artworks-spanning-two-wall-columns)).
- The wall renders its tiles in parts of 60 and loads the images of tiles near the screen in batches, so a tile may show the primed window of `ArtworkImage` for a moment before its image arrives; it never shows the `NoImage` cross for that ([ADR-0044](../decisions/0044-load-wall-images-near-the-screen.md)).
- A wall tile fades out while less than a fifth of it is visible below the top bar and the period strip and fades back in when a fifth is visible, over four times `--duration-short`. It stays fully visible under `prefers-reduced-motion` and without scripts.
- After an artwork is saved, the wall opens at the top and its tile carries an outline in `--color-fg` for about two seconds, which then fades over `--duration-short`.
- Saving an artwork whose title and authors match another one asks first with a small `Dialog` "Masz już takie dzieło": "W atelier jest już #0005 o tym samym tytule i autorach. Jeśli to inne dzieło, po prostu je zapisz.", with "Wróć do formularza" and "Zapisz mimo to". Its title is a statement, not a question ([ADR-0039](../decisions/0039-confirm-saving-a-duplicate-artwork.md)). Restoring an artwork from the trash asks the same question with the same `DuplicateDialog`, saying "Jeśli to inne dzieło, po prostu je przywróć.", with "Zostaw w Archiwum" and "Przywróć mimo to".
- After an edited artwork is saved, its page opens in place of the edit form in the browser history, so going back never returns to the form, and a `Toast` confirms "Zapisano zmiany w #0012.".
- A record number is always shown as `#` and at least four digits, padded with zeros: `#0012`, and `#12345` past 9999. This holds for tiles, page titles and messages. The app builds it with `formatRecordNumber` from `#lib/catalogue/record-number/record-number.ts`, and `ArtworkTile` formats its own `number`. Only the URL uses the bare number, `/atelier/12` ([ADR-0023](../decisions/0023-atelier-routes-and-commons-thumbnails.md)).
- An image in a form is the app's `ImageField` (the artwork image, an author's portrait): the passe-partout, the search, the own image dialog and the credit are shared, and the form passes its texts and its search query ([ADR-0056](../decisions/0056-author-portrait-years-of-life-and-sort-name.md)). From 768 px its column is sticky while the form scrolls: it stays under the top bar, and a column taller than the screen first scrolls to its end and then stays with its end above the save bar. Under the passe-partout come the lines about the source (the credit, then "Z Wikidata: …" or the state of the automatic search), the actions, any error, and the hints as one list of captions, each after a muted icon of its subject: `search` for "Wpisz tytuł i autora, żeby znaleźć obraz.", `pin` for the pin hint of a saved image and `clipboard` for the paste hint.
- In the add and edit form, the image actions sit under the passe-partout and act on the selected image slot ([ADR-0088](../decisions/0088-up-to-five-images-and-an-automatic-best-match.md)). Above the passe-partout a row of square slots shows the artwork's images, so the row does not move when images of different heights are picked: the first slot marked by a filled star centred in a dimmed band across the bottom of the thumbnail, like the tier of an exhibit in "Ekspozycja" (the tooltip "Główne" below it), an empty slot as a muted image icon, and a dashed "+" ("Dodaj kolejny obraz") until there are five. With a filled slot other than the first selected, the `inline` `TextButton` "Ustaw jako główne" with an outlined star at the end of the row makes it the main image, so the action and the mark share one symbol; the slot's "Usuń obraz" also removes an empty slot; removing the main image makes the next one main. Empty slots are left out on save.
- In the add form, while the main slot is empty, the image is looked up in Wikidata on its own 0.6 s after the title and an author (or "Autor nieznany") stop changing ([ADR-0088](../decisions/0088-up-to-five-images-and-an-automatic-best-match.md)): "Wyszukiwanie obrazu w Wikidata…" with "Przerwij" under the passe-partout while the slot is primed and its buttons are disabled, then the candidate that matches an author (or the single result without an author) fills the main slot with "Z Wikidata: {tytuł} · {autor} · {data}". The search button reads "Wybierz inny" while the slot holds an image from Wikidata and opens every candidate ([ADR-0089](../decisions/0089-one-search-button-and-the-word-obraz-in-the-image-field.md)). Without a match the line says "Nie udało się odnaleźć tego dzieła w Wikidata. Dodaj własny obraz z linku lub bezpośrednio z komputera.". Opening the search by hand stops the automatic search for the same title and authors. "Dodaj własny" (or "Zmień własny" once an own image is set) opens a default-size `Dialog` titled "Dodaj własny obraz" (or "Zmień własny obraz"). It opens with a highlighted paste area on `--color-surface`: a clipboard icon, the hint "Masz obraz w schowku? Po prostu naciśnij Ctrl+V." with the keys drawn as boxes (⌘V on a Mac), the buttons "Wklej ze schowka" and "Wybierz plik z dysku" side by side, and under them "Akceptowalne formaty zdjęć to: … Pliki większe niż 5 MB zostaną automatycznie zmniejszone."; a larger file or pasted image is made smaller once it is picked, with no message ([ADR-0091](../decisions/0091-make-large-own-images-smaller-in-the-browser.md)). Below the area, a URL field labelled "Jeśli wolisz, podaj po prostu adres obrazka" has "Użyj"; Enter in that field uses the URL instead of saving the form. Errors show under the buttons or the field. The dialog closes once an image is set; closing it without one leaves the image as it was and clears what was typed. "Wybierz plik z dysku" is the library `FilePicker` (a `Button` over a hidden native `input type="file"`), and the line under the buttons is the library `FieldMessage`, which describes both buttons. The file picker's `accept` lists both the allowed types and their extensions, so the system dialog filters files even where it does not know a type; the app still checks the picked file. With an image set, "Usuń obraz" clears it, and an own image is captioned "Twój obraz, widoczny tylko dla Ciebie.".
- On a touch screen (`pointer: coarse`) the own image dialog starts with "Zrób zdjęcie", a `FilePicker` with `capture="environment"`, and leaves out the Ctrl+V hint; with a mouse it shows neither change.
- An image can be pasted from the clipboard ([ADR-0032](../decisions/0032-paste-the-own-image-from-the-clipboard.md)). Ctrl+V in the form takes an image, or an `https` address, only when the focus is not in a field the learner types in; a paste in a text field or the notes editor is left to that field. A rejected pasted image shows its message under the image actions. The hint "Obraz ze schowka możesz też wkleić tutaj: Ctrl+V." sits under the image actions and shows only on devices with a fine pointer.
- The `alt` text of an artwork is "Title, Author". A decorative copy of the same image (for example a blurred backdrop) has `alt=""` and `aria-hidden="true"`.
- A caption uses `figure`, `figcaption` and `cite.artwork-title`, with author and date as a caption and the image credit below. The credit names Wikimedia Commons; when the image is not public domain or CC0 (a CC BY or CC BY-SA photo of an old work), it also names the photographer and the licence.
- A featured artwork sits on the stage: `--color-stage-bg` behind it and `--color-stage-fg` and `--color-stage-fg-muted` for its caption. The stage is dark in both themes, except in a review, where it follows the theme ([ADR-0251](../decisions/0251-follow-the-theme-on-the-review-stage.md)).
- The artwork view ([ADR-0026](../decisions/0026-artwork-view-as-a-stage-with-an-information-panel.md)) puts the image on the stage, over a blurred copy of the same image under `--color-scrim`, with the information panel beside it. The panel lists every field in the order of the form; an empty field shows a muted dash, with "Nie wpisano" for screen readers. The type and the era show their icon before the name, not a tag; the other category values are tags. A new icon never repeats one already used in the app for an era, a type of place, an artwork type or an action ([ADR-0066](../decisions/0066-icons-for-artwork-types-shown-like-eras.md)). A view that fills the screen below the top bar, like this one, passes `fill` to `AtelierLayout`.
- A panel that the learner can close leaves a narrow strip with a chevron and the panel name written vertically, which open it again. The panel opens and closes with the same width animation as the side menu, off under `prefers-reduced-motion`.
- Moving an artwork to the trash and deleting it permanently each ask first with a small `Dialog` ("Przenieść #0012 do Archiwum?", "Usunąć #0012 na zawsze?"); restoring does not. A `Toast` confirms each of the three ("Przeniesiono #0012 do kosza.", "Przywrócono #0012.", "Usunięto #0012 na zawsze."). An error stays in an `Alert` in the dialog, or above the list for restoring.
- Clicking an artwork image in a detail view opens it full screen on the stage background; Escape or the close button returns.
- A detail view (an artwork, a value of the card index) keeps its actions, "Edytuj" and "Usuń", only in the top bar. The body of the page does not repeat them, also when it is empty, and deleting works from the view without opening the form; the form has no "Usuń" ([ADR-0051](../decisions/0051-load-and-save-a-value-page.md)).

The image keeps its proportions and is never stretched, so its size does not depend on how much text stands beside it. On a phone the image comes first at full width ([ADR-0056](../decisions/0056-author-portrait-years-of-life-and-sort-name.md)).

The artwork view's way back leads to the wall even when the artwork was opened from a value page.

Kliknij, aby przyjrzeć się im bliżej.", leading to the wall filtered by the era and the missing-data option "rok poza epoką" ([ADR-0191](../decisions/0191-let-the-learner-change-the-era-bounds.md)).

## Reviews

- The reviews ([ADR-0061](../decisions/0061-review-the-collection-in-one-mixed-session.md)) are one page, `/atelier/review`, with three states: the start, the session and the summary. "Powtórki" in the menu sits between "Kalendarium" and "Archiwum" and shows the number of artworks waiting today in a small filled box after the label. Opening the reviews checks that number again: when the page's own counts differ, for example after reviews done in another session, the menu counter reloads. While the rail is collapsed the icon gets only a small filled square on its top right corner, without the number, so the icon stays centred; the number stays in the link's name for assistive technology. With nothing waiting it shows neither.
- The start names "Powtórki" in the top bar and opens with the `PageHeader` lead, which says how the reviews work (not on a phone), and under it the heading of today's round (`h2`, "Na dziś do powtórki zaplanowane masz 19 dzieł", or "Nic nowego do powtórki") with the plan for today and "Zacznij powtórkę", the view's one `primary` button, which on a phone stays at the bottom of the screen ([ADR-0071](../decisions/0071-put-the-plan-first-on-the-review-start.md)). The plan's parts stand apart with icons, `rotate-ccw` "12 powracających" and `sprout` "7 nowych". Under them the streak ([ADR-0078](../decisions/0078-show-a-streak-of-days-with-reviews-on-the-review-start.md), [ADR-0184](../decisions/0184-show-the-streak-and-the-round-summary-as-results.md)): the caption "Twoja seria powtórek", the number of days in Newsreader italic at `--font-size-3xl` in `--color-case-gold` with "dni z rzędu" beside it, and a strip of the last seven days labelled with the weekday and "dziś", the days of the streak in `--color-fg`, earlier days in `--color-tag`, today dashed until a review fills it; a screen reader hears one sentence instead. It is left out when the streak is zero. The scope ("Co powtarzamy?") and the form ("W jakiej formie?": "Mieszane", "Fiszki", "Quizy") sit behind the disclosure "Zmień zakres lub formę", a native `details` closed at first, in rows of `ToggleTag`s, one pressed at a time per row: each scope carries how many artworks wait in it, and one caption under the forms describes the chosen one. "Quizy" is left out when no quiz kind of the preferences can be asked: the title and the image quizzes are off and no artwork has a style (for the style quiz) or no pin names a glossary entry (for "Co to jest?"); the start then uses "Mieszane" ([ADR-0118](../decisions/0118-preferences-for-the-reviews-and-the-artwork-view.md)). The scope row offers "Cała kolekcja" always, then "Widziane na żywo" (the artworks of the visits in Kronika), an era, a period or a style, each only with at least 20 artworks with an image and at least 10 of them due today; with "Cała kolekcja" alone the row is not shown. With fewer than 20 artworks with an image the start shows an `EmptyState` "Powtórki staną się dostępne przy 20 dziełach" that says how many are missing, with "Dodaj dzieło" as a secondary link ([ADR-0130](../decisions/0130-show-empty-views-in-one-centred-pattern.md)). The side panel "Jak dobrze znasz swoje atelier?" shows one bar in `--color-fg`, `--color-fg-muted` and `--color-tag` for the settled, learning and new artworks, each group with a square of its shade, its number and one line, and under it up to four artworks that were hard lately as rows of a cropped thumbnail, the title and the authors, linking to their pages. The summary keeps its result as the `h1` and has no name in the top bar.

## Timeline

- "Kalendarium" sits in the menu between "Słowniczek" and "Powtórki", with the icon `calendar-range`, and shows one era at a time ([ADR-0093](../decisions/0093-show-the-collection-and-historical-events-on-a-timeline.md), [ADR-0094](../decisions/0094-name-the-timeline-kalendarium-and-simplify-its-header.md)). Its header is the `h1` "Kalendarium" with a lead, like the other views; the current era is the highlighted segment of the era strip, with no heading of its own.
- The era strip is the only era control: `--size-control` high, every era as wide as the others, with no break mark and no frame of what is in view ([ADR-0242](../decisions/0242-polish-the-era-strip-axis-and-event-names-of-kalendarium.md)). Each segment shows the era's icon and its name where it fits, the current one filled in `--color-fg-muted`. Under the strip the current era's name stands centred like the eras in Kartoteka, in the title font in italics at `--font-size-2xl`, with `--spacing-3` above and below, and under it the previous era is a small muted text button with an arrow on the left, the next one on the right, and the scale steps as `ToggleTag`s in the middle between small muted "−" and "+" icon buttons, dimmed at the ends of the scale.
- Prehistory starts at 40000 BCE, or at the learner's oldest dated entry rounded down to a millennium when that is older ([ADR-0097](../decisions/0097-start-prehistory-at-the-oldest-entry-on-the-timeline.md)).
- The stage is a `group` "Oś czasu" whose dots and events are buttons; the reading line's year label is the `slider` over the years of the era, so with the focus on it the arrow keys pan and "+" and "−" change the step, and pressing the empty stage focuses it. The line above the stage is `aria-hidden`; a visually hidden live copy of it updates half a second after the view stops ([ADR-0098](../decisions/0098-bound-years-and-make-the-timeline-stage-accessible.md)). Dragging pans, and the wheel and a pinch move one step around the pointer. A step change animates over 400 ms, at once under `prefers-reduced-motion`.
- On the stage, the axis names millennia, centuries ("XVII w.") or decades in muted captions, thin lines in `--color-tag` cross it at the start of every century (or millennium when centuries are closer than 20 px), the margin outside the era is filled with `--color-tag`, and the events stand in a band on `--color-surface` above the artworks, both zones labelled in small capitals. The reading line in the middle is `--color-highlight`, with the year in a box of the same colour at the bottom. When the longest label of the era does not fit its century or millennium, only every 2nd, 5th, 10th, 20th, 50th or 100th one is labelled, counted from year 1, and its label spans that many segments; the lines stay at every one ([ADR-0242](../decisions/0242-polish-the-era-strip-axis-and-event-names-of-kalendarium.md)).
- Every artwork with a year is a 10 px circle in `--color-fg` at its end year, drawn as SVG (corners stay square everywhere else), with a hairline in `--color-fg-muted` from its start year when it has a year span. Dots are placed across the artworks zone at random without overlapping, seeded by the artwork, so the picture is the same on every visit. A dot is a button named by the title and the date, with a hit area of about 32 px. Hovering it, or focusing it from the keyboard, shows the artwork's `ArtworkTile` beside it as an inert preview, with no link. A mouse click does nothing; a tap (or Enter) selects the dot, marks it in `--color-highlight` and keeps the preview, and a second tap, a tap on the empty stage or Escape unselects it ([ADR-0095](../decisions/0095-filter-the-timeline-with-period-and-style-lanes.md)).
- In the event band a period is a ribbon on `--color-tag` with a bar in `--color-fg-muted` at its start and its name inside, or after it when it does not fit; a single year or a short period is a pin (a rotated square) with its name. A name longer than 200 px is cut with an ellipsis, and the lanes count only the cut width; the library `Tooltip` shows the whole name on hover, opening into the stage (below the event in the first lane and above it in the others; on a phone below the name in the upper half of the stage and above it in the lower half), and the hovered event stands above its neighbours. Events are packed into lanes counting their names, at most 4 (3 on a phone), the band as high as the era needs at any step, and what does not fit is "+n" at the right with the full sentence for assistive technology. Without events the band says "Nie ma tu jeszcze wydarzeń."; on a phone the line stands above the stage and the band takes no room ([ADR-0130](../decisions/0130-show-empty-views-in-one-centred-pattern.md)). An event cut at the era's edge carries "‹" or "›". A name that would run past the end of the era or the edge of the stage stands before its pin or ribbon when it fits there, and a name inside a ribbon that starts before the visible part moves into it ([ADR-0242](../decisions/0242-polish-the-era-strip-axis-and-event-names-of-kalendarium.md)).
- A chosen event turns `--color-highlight` and tints its time over the stage with dashed edges. From 768 px it opens a popover anchored to its bar or diamond ([ADR-0241](../decisions/0241-show-a-timeline-event-in-a-popover-and-drop-the-artworks-at-the-reading-line.md)): an interactive `PopoverCard` about 360 px wide, below the event or above it without room, kept sideways within the stage (its `boundary`) and placed again while the view moves. It holds "Wydarzenie" or "Okres", the name as `h2` and a link to the event's page, the date and the length, the description cut to six lines, the Wikipedia source, "Pokaż cały okres na osi" (an underlined text button without padding, aligned with the texts), the artworks of its time as buttons that choose them, and "Edytuj" (a link to the form) and "Usuń" (`danger`) as icon-only buttons in the corner by the name, named in a `Tooltip` below them. Escape, a click outside or any action in it closes it and unselects the event; Escape and the actions give the focus back to the event. Only one thing is open on the stage: choosing an event unpins an artwork's preview and the other way round. Below 768 px the event opens the same content as a card under the stage, with "Edytuj" and "Usuń" as labelled buttons on the right. "Usuń" asks in a small `Dialog` "Usunąć wydarzenie „…”?" and a `Toast` confirms. Nothing stands between the filter tags and the stage, so the stage never moves while the learner pans; the events at the reading line are spoken only for a screen reader ([ADR-0107](../decisions/0107-drop-the-line-above-the-timeline.md)).
- Every event has a page at `/atelier/timeline/events/<id>`, opened from the name on the event card (a link) and from its row on the events tab of the card index: the kind line "Okres · n dzieł" or "Wydarzenie · n dzieł" with the icon of the tab, the name as `h1`, the date and the length, the description with its Wikipedia source, and "Dzieła z tego czasu" as a wall of the artworks whose time overlaps the event, oldest first, after the relations band, or "W tym czasie nie powstało żadne dzieło z Twojej kolekcji.". "Edytuj" and "Usuń" stand in the top bar with "Kalendarium" as the way back; a save started there returns to the page with "Zapisano …", and a delete goes to the card index ([ADR-0190](../decisions/0190-show-the-relations-of-a-value-on-its-page.md)).
- "Dodaj wydarzenie" in the top bar of the timeline (from 768 px; on a phone the bottom bar adds) is its one `primary` button. The event form is a page like the glossary entry form, as wide: "Nazwa", the date as `YearGroup` with `YearInput` and the same rules as the date of creation ("Rok", or "Lata" with "Od – do"), and "Opis" with a counter up to 300 characters. Saving returns to the timeline in the era of the event, at the closest step that shows it whole, with a `Toast` "Zapisano wydarzenie „…”.".
- The event form suggests the dates and the first sentence of a Polish Wikipedia article ([ADR-0096](../decisions/0096-suggest-an-events-dates-and-description-from-wikipedia.md)): while it searches, the dates and the description it may fill are locked ([ADR-0150](../decisions/0150-lock-the-fields-an-external-fetch-fills.md)); it says nothing when it finds nothing, and after a failure "Nie udało się połączyć z Wikipedią. …" with "Szukaj jeszcze raz" stands under "Opis". After a match, the caption "Na podstawie: Wikipedia, „…”, CC BY-SA 4.0" stands under "Opis" with the text buttons "Wybierz inny artykuł" (the glossary's article dialog, with each article's dates) and "Usuń źródło". The event card repeats the source line with links to the article and the licence.
- Below 768 px the stage turns vertical (`aria-orientation`): time runs from top to bottom over 66% of the screen's height (440 to 820 px), the axis labels stand in a column on the left, the event band is a column of lanes 22 px wide with the names written vertically, the artworks spread across the rest of the width, and the reading line runs across with the year on the right. Dragging up and down pans, a pinch moves one step, and the arrow keys pan by a quarter of the view in both layouts. The stage takes the touch, so the page scrolls outside it.
- "Filtry" at the top right of the header opens the same `FilterSidePanel` as the wall (a full-screen `Dialog` with "Pokaż {n} dzieł" below 768 px): "Okresy i style" with the hint "Wybierz maksymalnie 5 z epoki {epoka}." (or "Wybrano 5. …", the other values disabled), the periods and styles as `ToggleTag`s with a dot in their lane's colour once chosen, the favourites toggle, "Typ dzieła" tiles, "Autor" and, under "Widok", the switches "Wydarzenia" and "Zakresy dat dzieł" (off, an artwork with a range of years shows only its dot, which alone answers a click). Counts are of the era in view. The active filters are `FilterTags` above the reading line's bar, a period or style tag with its lane's colour dot.
- On a larger screen every chosen period or style is a lane of the artworks zone, at least 72 px high, split by a hairline and labelled "Barok · 32" with its colour dot; its dots take `--color-lane-1` to `--color-lane-5` in the order chosen. In the vertical layout a dot takes the colour of its first chosen lane. With nothing matching, the zone says "W tej epoce nie ma dzieł, które pasują do filtrów."
- Layout rules that are not CSS (axis segments and their labels, the place of event names, the steps, the start era, the stage's geometry in both orientations) are pure functions in `#lib/timeline` with unit tests.

## Chronicle

- "Kronika" sits in the menu after "Kalendarium", with the icon `footprints` ([ADR-0128](../decisions/0128-log-museum-visits-in-a-chronicle.md)). Its header is the lead with the number of visits and of the artworks seen in person beside it; "Dodaj wizytę" (the `plus` alone on a phone) is its one `primary` button. The visits stand newest first in a `Disclosure` per year with the number of its visits; only the current year, or the newest one when the current year has no visits, is open at first.
- A visit is a ticket on `--color-surface`: the date on the left (the day large with the month under it, or the month alone, never the year, which the group names; a visit known only to the year shows no date there, and the whole date stays in the accessible name), then the place as a link, its type with its icon and the country, the number of artworks seen and the first two lines of the note as plain text. The stub (`TicketStub`) is cut from it by a zigzag (32 px period, 14 px deep) through which the page shows, which shows the first artwork of the visit with an image as a faded, cropped backdrop, a decorative copy hidden from assistive technology that loads when it comes near the screen. On a phone the zigzag runs across the card and the stub is a band under it. From 768 px the tickets of the list take half the width of the content, at least `--size-content-narrow`.
- The visit view starts with the same ticket, headed "Wizyta" and the place as `h1`, with the year under the day or the month and the number of artworks seen in the stub; the note follows in a `Section` with the text spine, and the artworks fill a wall "Widziane na żywo" without a count of its own, since the stub gives it. An artwork in the trash is left out. "Edytuj" and "Usuń" stand in the top bar; "Usuń" asks in a small `Dialog` named by the date, and the list confirms the delete with a `Toast`.
- The form has "Miejsce" (the place field of the artwork form, with the starter museums; its hint only in a new visit), "Data" (a group of "Dzień", "Miesiąc" as a `Select` of the month names and "Rok", each optional but the year, with the hint that a year is enough and each error under its own field), "Notatki" and the field "Dzieła": a search over the collection by title and author, then the artworks of the chosen place under "Z tego miejsca" and the ones added from the search under "Z innych miejsc". Each artwork is a tile like the wall's: a square cropped image on the passe-partout with the title on its bottom edge and a tick mark in the top right corner of the image (filled when ticked, an empty box when not), over a visually hidden native checkbox named by the title; the tile shows the keyboard focus. All are ticked for a new visit; an unticked artwork stays in its group, dimmed. Changing the place replaces the artworks of the old place and keeps the added ones, but removing the place and choosing it again keeps its ticks, and coming back to the saved place of an edited visit brings back its saved ticks; an edited visit opens as it was saved, and the artworks of the visit that are in the trash are kept on save. Saving opens the visit in place of the form with a `Toast` "Zapisano wizytę: {miejsce}, {data}.".

- The artwork view lists the visits of the artwork under its information table, before the notes, in a closed `Disclosure` headed by the `footprints` icon and "Widziane na żywo · {n} wizyty", newest first. Each visit is a `SmallTicket`, a link to the visit: the date with its year on the left and the place in italic on the right, cut from the date by a smaller zigzag (`TicketStub` with `small`). An artwork without visits shows nothing there.
- A place page in the card index lists the visits to the place the same way, under the type and the country and before the summary and the notes, headed "Z Twojej kroniki · {n} wizyty". Its tickets leave out the place and show the number of artworks seen on the visit ("4 dzieła na żywo"), or nothing for a visit without artworks. A place without visits shows nothing there.
- The filter panel of the wall has "Widziane na żywo" with the `footprints` icon and its count next to "Ulubione", both a `FlagToggle` (the heart filled when pressed, the footprints not); it is kept in the address as `seen=1` and has a tag that names the field only. There is no "not yet" choice.
- A visit whose note links to a value or an artwork is listed under "Wspominasz o tym w notatkach" as "Wizyta" with its place and its date as far as it is known ("Louvre · 12.10.2026"). A place with visits counts as used in the card index, so it has no "Usuń" until its visits are gone, merging two places moves their visits, and the place fields of the visit and artwork forms suggest it even when no artwork has it.

- The comparison view is two stages side by side in equal columns, each built like the stage of the artwork view (blurred backdrop, scrim, passe-partout) with the caption centred under the image and "Zmień dzieło" as a `TextButton`. On a phone the stages stack ([ADR-0203](../decisions/0203-show-the-palette-on-the-stage-and-compare-two-artworks-side-by-side.md)).
- The empty half is on `--color-bg` without an outline, so it reads as part of the comparison: the question, with the other artwork's title in the artwork title font ("Z czym porównać _Mona Lisa_?"), a `SearchField` and the atelier as `ArtworkTile`s in three columns, which scroll inside the half with the overlay scrollbar.
- The palette and loupe icons sit once, in the top right corner of the comparison, and act on both images. They show only once both halves hold an artwork; emptying a half switches the loupe and the palettes off.

## Statistics

- "Statystyki" has no item in the menu: the artwork count over the wall is its way in, a link of the count and the `chart-column` icon (`WallCount`) with a `Tooltip` "Statystyki", muted like a caption and in `--color-fg` on hover ([ADR-0171](../decisions/0171-show-statistics-of-the-collection-from-the-wall.md)).
- The view is a detail page in one column at most `--size-content-wide` wide ([ADR-0177](../decisions/0177-show-the-statistics-at-the-wide-content-width.md)): "←" and "Statystyki" in the top bar, the lead, then the sections in the order and with the names of [ADR-0175](../decisions/0175-design-the-statistics-view.md), `--spacing-16` apart, each opened like a room of "Ekspozycja" by a hairline in `--color-line` above it and its `h2` in the title font, in italics, at `--font-size-2xl` ([ADR-0239](../decisions/0239-set-the-statistics-sections-apart-like-rooms.md)), in the monochrome theme tokens.
- "W pamięci" reuses `KnowledgeBar` and `ArtworkRow` of the review start's panel. "Nabytki" is `ColumnChart`, SVG columns that are keyboard buttons showing their description above them.
- "Stan zbiorów" is a `dl` of four numbers in a row, eight in all, the number bold over its label, `xl` over `sm` from 768 px and `lg` over `xs` on a phone, the labels wrapping.
- The counts of "Kompozycja" and "Na pierwszym planie" come from the wall's own `filterValuesOf` and link through `wallHref`, which writes the matching wall filter, so a count and the wall it opens always agree. An artwork without an author counts as "Autor nieznany", as on the wall. The bars are `BarList` (name, bar, number; on a phone the bar under the name), the table `CrossTable` (cells shaded with `color-mix` of `--color-fg`, the first column sticky and 8–16 rem wide with long names cut by an ellipsis, headers wrapping at 5–10 rem, sideways scrolling in its own box; names in the bars are cut the same way, each with its full name in `title`), the two tag rows `ToggleTag` groups side by side from 768 px.

## Glossary

- The glossary ([ADR-0074](../decisions/0074-keep-a-glossary-of-terms-with-definitions-from-wikipedia.md)) is "Słowniczek" in the menu ([ADR-0080](../decisions/0080-keep-the-glossary-name-slowniczek.md)), after "Kartoteka", with the icon `book-a`. Its six categories each have an icon used nowhere else (`person-standing`, `drafting-compass`, `paintbrush`, `cuboid`, `pipette`, `lightbulb`) (defined in `lib/glossary/categories/categories.ts`); `categories.spec.ts` checks them against the eras, the types of place, the artwork types and the menu.
- The number of all entries stands beside the lead, like the wall's count of artworks. Under the lead, a `SearchField` from 20 entries and then the category `ToggleTag`s with their numbers (a category with no entries is disabled) form one block closed by a hairline, set apart from the list. On a phone the search and the order share one row, the order shrunk to its icon (`iconOnPhone`), and the categories stand in one row that scrolls sideways from edge to edge ([ADR-0252](../decisions/0252-overhaul-the-app-on-a-phone.md)). The list has `--spacing-12` between letters (`--spacing-6` on a phone) and `--spacing-8` between entries, with the entries sorted by name (or by their sort name, when set) in Polish order under their capital first letters: to the left of them from 768 px with a full-width hairline above every letter after the first, above them over a hairline on a phone, at `--font-size-lg`, sticking under the top bar while their entries scroll by ([ADR-0077](../decisions/0077-trim-the-wikipedia-lead-and-polish-the-glossary-list.md), [ADR-0079](../decisions/0079-connect-the-lexicon-and-suggest-forms-from-wiktionary.md)). An entry shows its name, its category as a small icon and name, and the first sentence of its definition (two when the first has three words or fewer) in at most two lines. "Dodaj pojęcie" is the view's `primary` button. From twenty entries, when the list shows more than one letter, `LetterIndex` stands at the right edge, from 768 px still and centred in the height below the top bar, on a phone from the list up to the top bar ([ADR-0245](../decisions/0245-stand-the-glossary-letter-index-in-the-middle-of-the-screen.md)): a column of the shown letters ("Litery"), the current one in bold with `aria-current` (the chosen letter until the learner scrolls on their own, and the last letter once the page cannot scroll further); a letter scrolls its section to the top, smoothly unless reduced motion is asked for, and the list keeps room for the column. On a phone a finger that slides along the column jumps to the letter under it at once and shows that letter large beside the finger, in the title font on `--color-fg`, until the finger lifts ([ADR-0252](../decisions/0252-overhaul-the-app-on-a-phone.md)).
- An entry's page is built like a value page: category in small capitals with its icon, the name in the title font, the synonyms in one caption line "też: …" (inflected forms are never shown), the definition as a quote with a bar and, under it inside the bar, the source line that links the article and the licence. "Edytuj" and "Usuń" sit only in the top bar. Its "Słowniczek" in the top bar goes back through the browser history when the entry was opened from the list, so the list returns to its scroll position with its search and categories kept (a page snapshot); otherwise it links to the top of the glossary.
- Above "Na dziełach", an entry's page shows "Detale" with their count while a pin of the entry keeps a loupe view ([ADR-0192](../decisions/0192-refresh-the-glossary-list-and-show-the-fragments-of-a-term.md)): one row of round lenses, 160 px from 768 px and 128 px on a phone, each with the artwork title in the title font and the record number under it, the pin text in a `title` hint, and a link to the artwork with `?pin=`. The row scrolls sideways; from 768 px, while it overflows, `IconButton`s with `chevron-left` and `chevron-right` stand at its ends. A lens shows the stored crop of its pin (`TermFragments`); without a crop, or when it does not load, it cuts the same square from a medium image of the pin (960 px from Commons, the 500 px thumbnail of an own image) with CSS, blurry at a strong zoom ([ATL-531](https://linear.app/kamil-nawrot/issue/ATL-531)).
- The form searches Polish Wikipedia by itself once the name and the category are set and the definition is empty or still the fetched text, after the learner pauses typing. A definition the learner wrote or changed is never replaced without asking ("Zastąpić twoją definicję?"); an entry opened for editing counts as changed, because the app does not keep the original text. The article can be changed with "Wybierz inny artykuł", the source removed with "Usuń źródło".
- Under the name, the checkbox "Sortuj inaczej niż po nazwie" shows "Sortuj jako", as for authors. After the definition come "Synonimy", a `ValueField` that is always visible, and "Odmiana": a frame with the number of forms and the text button "Pokaż formy" / "Zwiń" over a `ValueField` of the forms, collapsed when the entry opens with forms and open while there are none. Marking in notes and "Pojawia się w notatkach" match the name, the synonyms and the forms ([ADR-0079](../decisions/0079-connect-the-lexicon-and-suggest-forms-from-wiktionary.md)).
- A new entry fetches its forms from Polish Wiktionary (`lib/glossary/wiktionary/wiktionary.ts`) once the name and the category are set and the forms are empty or still the fetched ones, after the same pause as the definition: one word from the noun's declension template, two words as a phrase page or combined from a noun and an adjective by case, number and gender. Fetched forms arrive collapsed. The frame says "Wyszukiwanie odmiany w Wikisłowniku…" with "Przerwij" while it fetches, and the forms are locked meanwhile, and without forms it says why: a person or a name of more than two words is not looked up, nothing was found, or Wiktionary did not answer ("Szukaj jeszcze raz"). An entry opened for editing never fetches by itself: with no forms it offers "Pobierz z Wikisłownika", and after its name changes "Pobierz ponownie", which replaces the forms.

## Settings

- "Ustawienia" is a module page reached from the avatar row at the top of the menu (the avatar, 40 px when the menu is open, the name, and the email in smaller `--color-fg-muted` text under it, with the whole email in a `title`), which is a link with the same hover and current-page marks as the other items. The row keeps one height, with room for two lines, so the items under it do not move when the menu opens, and a hairline separates it from them. The page has the library `Tabs` "Profil", "Konto", "Powtórki", "Widok dzieła", "Źródła" and "Dane", with the chosen tab in the address ([ADR-0117](../decisions/0117-settings-view-in-tabs-opened-from-the-avatar.md)). The top bar has the arrow of `BackLink` to the view the learner came from, falling back to "Atelier", then "Ustawienia".
- Every part saves on its own. "Profil", "Powtórki", "Widok dzieła" and "Źródła" keep "Anuluj" and "Zapisz profil" or "Zapisz ustawienia" in `FormActions`, the bar at the bottom of the screen, and ask "Odrzucić zmiany?" before the learner leaves them with changes; "Konto" has "Zmień adres" and "Zmień hasło" under their own fields, then the section "Regulamin i Polityka prywatności" with the accepted version of the terms and the links to both, and "Usuń konto" last, and "Dane" has the sections "Eksport" ("Pobierz atelier") and "Import" ("Wybierz plik ZIP"), each under its description, with the progress next to the button and the import disabled, with the reason in its hint, in an atelier that is not empty. A save confirms with a `Toast`; a field error stands under its field, a failed save in an `Alert` at the top of the tab.
- A tab with parts ("Konto", "Powtórki", "Dane") puts each in a `SettingsSection` ([ADR-0186](../decisions/0186-tidy-up-the-settings-view.md)): an `h2`, then the content at `--size-content-default` with `--spacing-4` under the heading, and a hairline above every section but the first that runs the full width of the tab, like the line under the tabs. A tab without parts ("Widok dzieła", "Źródła") opens with a short muted description of what it sets.
- In "Źródła" each source is a `Switch`. A fetch that is switched off starts only from a text button in the form ("Szukaj w Wikipedii", "Pobierz z Wikisłownika"), never by itself.
- "Powtórki" has the sections "Sesja" (the size of a session, new artworks a day, the default form, "Powtórka swobodna"), "Quizy" (the quiz kinds) and "Pytania dodatkowe" ("Pytania ze Słowniczka" with "Liczba pytań w sesji" under it, disabled while it is off, then the gap in a note and the questions about time). Its labels are short noun phrases, with a muted hint under a switch whose name alone does not say what happens.
- In "Powtórki" and "Widok dzieła" a question with a few values (the size of a session, the form) is a row of `ToggleTag`s under a label in the style of a field label, a set of kinds that may be switched off one by one is `Checkbox`es with a hint of how many must stay on, and a single yes or no is a `Switch`. A choice that would leave a preference that cannot be saved is kept from being made: the last matching quiz kind ("Dopasowywanie …") left on is disabled, and the hint under the group says why.
- In "Profil" the avatar fills a passe-partout frame (a padded `--color-surface` mat with a hairline) in a column as wide as the fields beside it (`--size-content-narrow`), with the buttons that add or change and remove the photo under it as text buttons with an icon ("Dodaj zdjęcie" or "Zmień zdjęcie", and "Usuń zdjęcie" in `danger`), like the image of a form. Under the name stand the `Switch` "Pokazuj stopień i Ekspozycję" with its hint and then "Forma stopni", disabled while the switch is off. The email of the account is shown only in "Konto", in bold in the hint of the new address.
- In "Dane" the used space is a thick `Meter` on the dim track, so it does not read as one more divider, with the used megabytes in bold in the sentence above it.
- Fields take `--size-content-default`, like every form. A choice of one value from a few (the session size, the start form) is a row of `ToggleTag`s, one pressed at a time, like the review start; an on/off preference is a `Switch`; a set of things to include (the quiz kinds) is a column of `Checkbox`es.

## Logo

- The brand is the library `Logo` (mark and wordmark) or `LogoMark` (mark only), never text styled to look like a logo. Both follow the text colour. Why it looks this way: [ADR-0020](../decisions/0020-logo-passe-partout-mark-and-wordmark.md).
- `Logo` takes its accessible name from `m.app.name`. `LogoMark` is decorative unless it gets a `label`.
- Content or animation inside the mark (for example the strokes of `LoadingScreen`) is passed as SVG children of `LogoMark`.

## Library texts

The library has English defaults for its own words (alert labels, show and hide password, remove tag). The app sets the Polish texts once in the root layout with `setUiMessages(m.ui)`, which keeps them in the library module for the whole app, and its browser tests set them the same way ([ADR-0087](../decisions/0087-set-library-texts-once-for-the-whole-app.md)). A view passes a text prop such as `label` only when one place needs different wording, never to repeat `m.ui`.

## Storybook

Every library component has stories for each variant and state, including error and disabled. Components that belong to the app (for example `AuthLayout`) are not in Storybook.
